# Kubernetes limits

The stated limits, takeover behaviour and EKS prerequisites of the kubernetes executor; the map to the code is [kubernetes.md](kubernetes.md).

## Stated limits

- Stated limit: a runner still RUNNING when its driver is lost, its agent released by the supervisor, is taken over: the next claim rebinds the supervisor (`rebind`), the supervisor must poll the new endpoint within `SUPERVISOR_REBIND_DELIVERY_MS`, and no sync, setup or `go` follows; one never released is swept by the next claim's re-claim fence and the job redone in its session and tree, an interruption inside the budget; one whose agent exited is taken over the same way while its supervisor still serves (no `supervisor: stopped serving the steps`), its report delivered to the new holder; one whose supervisor stopped serving is waited out (`finalizeWaitMs`, `driver/src/supervisor-plan.ts`) and adopted with its logged report, and a lost driver still alive steps into it until it learns its lease was lost, then hangs up on the group's tokens (`depart`), the wait outlasting that learning (one heartbeat) and the group's `takeoverBoundMs`. A finished one is adoptable until its Job's one-hour `ttlSecondsAfterFinished`. `driver/src/k8s/k8s-adopt.ts`, `driver/src/docker/docker-close-read.ts`.
- A taken-over run's agent (publish, review and ad-hoc gate runs, `POST /gate/run`) and exporter reach the new holder through the supervisor's relay (`serveRelay`); a request in flight across the rebind is hung up on (the exporter retries it; the agent's proxy answers 502), and the transcript continues under the new claim from its first unacknowledged byte. `driver/test/supervisor.test.ts`, `driver/test/control-proxy.test.ts`.
- A taken-over run's agent gate requests reach the new holder the same way, and the agent holds no gate URL or token (`factory-gate` asks the control socket); an ad-hoc gate run in flight across the rebind is hung up on and re-asked, so it may run on both holders, never exactly once. `driver/src/loop/loop-gates.ts`.
- A driver cut off from the board stops at its own lease clock, never at a failed beat: one lease after the last acknowledged beat's send time it departs (runner and group left for the next claim, never a verdict) or kills a runner not yet launched, and fences the conclusion's board calls; the review beat and the reclaim renew keep their own. `driver/src/loop/loop-lease.ts`, `driver/test/loop-lease-lapse.test.ts`.
- Stated limit: a rebind reaches a live supervisor only once the kubelet refreshes the attempt Secret's volume — up to its sync period (default one minute) plus its cache delay; docker's write is seen on the supervisor's next control poll. `driver/src/k8s/k8s-binding.ts`.
- Stated limit: a node going NotReady is seen only when the cluster acts on it (taint-based eviction, default ~300 s, then the Job's `FailureTarget`/`Failed` or the pod's deletion); the driver never treats stale pod status as loss. `driver/src/group-watch.ts`.
- Stated limit: a takeover needs `driver.rebindGraceMs` to outlast that refresh (~60 s measured); a shorter grace ends the group before the new holder's binding arrives. `charts/factory/values.yaml`, `scripts/test-k8s.sh`.
- Stated limit: why a driver ended a run is recorded on the attempt only where it outlives the kill — a hard-kill deletes the Job, its record, its Secrets and its claim before `end` reaches the board, a refused record is none — and such a run is redone in its tree and session. `driver/src/termination.ts`, `driver/src/k8s/k8s-runner.ts` (`killRunner`).
- Stated limit: a verdict neither staged nor completed within one lease leaves its group and checkout claim to the next claim: its agent outcome is adopted and resumes after the last post-run phase checkpointed on the board (`gates` bound to the tree's fingerprint, then `post`, `publish`); a phase whose checkpoint is missing, unreadable or bound to another tree runs again, with every phase after it, and an attempt with no budget left can retire `dead` before it is adopted. `driver/src/loop/loop-conclusion.ts` (`end`), `driver/src/loop/loop-phase-checkpoints.ts`.
- Stated limit: a declared service image needs `sh`, `cat` and a writable `/tmp` — its liveness probe (`driver/src/scripts/service-generation-probe.sh`) fails on every run without them.
- Stated limit: the kubernetes question round trip (a real claude CLI through the bridge) is not run on a kind cluster — the cluster lane installs the stub executor image. The relay is pinned offline in `driver/test/k8s/` and run through the supervisor with the stub's question (`--phase control`); docker's lane is `ask_roundtrip_lane` in `scripts/test-jobs.sh`.
- Deliberate docker divergences: no cpu-request flag, no node scheduling, no RuntimeClass (`RUNNER_RUNTIME_CLASS`), no `imagePullSecrets` twin, no admission equivalent; on docker (development only) service listeners are reachable by IP on the compose network (`driver/src/docker/docker-mailbox.ts`).
- A node loss never spends the poison interruption budget: the driver flags `nodeLoss` only on structured evidence — a drain, a runner pod the control plane marked a disruption target, evicted or gone (`runnerLossOf`), a pod seen then gone before its supervisor's first contact, and a lost supervisor channel only when the pod list confirms the group was taken away (`groupTakenAway` answers `taken`, `kept` or `unknown`: a live pod whose supervisor crashed or was OOM-killed is `kept` and keeps counting; a failed, timed-out, empty or malformed read is `unknown`, a blocked interrupt that spends no budget — stated limit: a persistently faulty apiserver under a supervisor that keeps closing re-queues the task with no bound); the docker counterpart is a removed container; lease expiry stays unflagged
- Stated limit: a suspended organization's task volumes are kept for the whole suspension, so a thread's `taskVolume.size` claim is billed until the organization is reactivated or deleted; the suspension stops its runner pods, never its volumes.
- The secret store's `gcp` backend authenticates through the dashboard service account's `iam.gke.io/gcp-service-account` annotation, so no pod holds a credential; `eks.amazonaws.com/skip-containers: wait-for-database` is always set (limit: EKS Pod Identity has no per-container exclusion, so its credentials reach the init container too).

## EKS prerequisites

Each is silent when wrong. Walk: [eks-runbook.md](eks-runbook.md); measured claims: [limits.md](limits.md).

- **Node-level IMDS defence** — `httpPutResponseHopLimit: 1` on the runner node group.
- **The VPC CNI add-on needs `enableNetworkPolicy: true`**, enforcing only on EC2 Linux nodes — not Fargate, not Windows. Without it the NetworkPolicy is admitted and inert.
- **Every runner pod is a Job's** — the driver creates no bare pod — closing AWS's standalone-pod caveat (`charts/factory/templates/driver-rbac.yaml`).
- **metrics-server is not installed by default** (vitals read null), and **`blockedCidrs` blocks the VPC too** — a runner that must reach a VPC endpoint needs that host in `isolation.allowedCidrs` as a /32.
- **The task volume** needs the EBS CSI driver add-on running and a StorageClass with `provisioner: ebs.csi.aws.com`, `volumeBindingMode: WaitForFirstConsumer`, `type: gp3`, `reclaimPolicy: Delete`, named by `taskVolume.storageClass` (the default `''` fits kind, nothing on EKS); the operator creates it ([eks-runbook.md](eks-runbook.md)). **Only the driver's task pods set `fsGroup`** (`core/test/docs.eks-storage.test.ts`), which makes the block volume writable by uid 1000. Stated limit: `ReadWriteOncePod` on the EBS CSI driver and the chart on EKS have never been observed.

## Isolation: assumptions and residuals

Controls and why none of this is kernel or VM isolation: [security.md](security.md). The deployment must provide
**A CNI that enforces NetworkPolicy**, **ValidatingAdmissionPolicy, native sidecars and `pods/resize`, Kubernetes ≥ 1.33**,
the IMDS defence. Residuals:

- **IPv6 egress is not covered**; every rule is IPv4.
- A runner can **reach the driver pod on any port** (the gate endpoint has an ephemeral port). Runner pods take no ingress, so one attempt cannot reach another (`--netpol` pins it denied); a declared service name resolves to `127.0.0.1` through `hostAliases`, never through DNS (#296).
- An apiserver or node address that is **PUBLIC is not covered** by `blockedCidrs`. A NetworkPolicy also **says nothing about HTTP routes**.
- A thread's disk is its `taskVolume.size` request, a cap only where the provisioner enforces it; `REVIEWER_UID` separates signals, not files.
