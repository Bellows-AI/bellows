## Invariants

- **A cumulative counter is reduced to its high-water mark per raw series, never `sum(value)`** — in `002_views.repeatable.sql` and again in `core/src/token-contributions.ts`; series are summed, and unspecified temporality is never added. Guarded by `server/test-db/telemetry.sql.test.ts` and `server/test-db/telemetry.token-reduction.test.ts`, which holds both to the same totals.
- **Every view reads `metric_point_used`, never `metric_point`** — `session_source` picks one source per session, OTEL over transcript; reading the table reintroduces the double count.
- **A point belongs to the organization whose credential wrote it** (`metric_point.org_id`): every view carries `org_id` through each grouping, join and output, and each usage read takes only its own org's points; a null-org point (older, matched to no single org's evidence) is in none. `server/test-db/telemetry.org-binding.test.ts`.
- **A session another attempt or organization holds is refused on both write routes** (`claimSessions`): an attempt writes the sessions bound to it or to nothing yet, a personal token any session no other org holds. A refused point is a partial rejection, a refused branch report a 403; a failed lookup is a 503 that writes nothing. `server/test/routes.ingest.test.ts`.
- **A session has one owning organization** (`telemetry_session_owner`): the first credential's org to write it, or the org its first binding reserves it to; both routes refuse any other, and a binding of a session another org owns is not recorded (`job-store-provenance.ts`). This is why `metric_point_dedup` needs no `org_id`. A point stored with no org is repaired when its session's evidence arrives; the two sides serialize on a per-session advisory lock (148), so neither misses the other. `server/test-db/telemetry.org-binding.test.ts`.
- **Nanosecond timestamps divide by `1e6`, not `1e9`** (`server/src/telemetry/otlp.ts`).
- **Attribute keys are allowlisted; metric names are denylisted.** A new identity attribute is dropped by default; an unknown metric still lands in `metric_point` unmapped. `attrs.series` is the one-way sha256 digest of the full pre-allowlist attributes; the dropped values are never stored.
- **A session key is `(agent, session id)` and has one owner, resolved before any join** (`core/src/usage-ownership.ts`): the tenant's board evidence (an execution's author, repo and canonical task) or its branch reports. No evidence, or evidence from a second organization, keeps the key out of every tenant read; two tasks or two repos make it unresolved, never a `min()`. `server/test-db/token-reconciliation.test.ts`.
- **No monetary field exists** — `claude_code.cost.usage` and `opencode.cost.usage` are refused at the collector and again at the ingest route.
- **`on conflict do nothing` on `metric_point`, never `do update`** — an update would move `received_at`, the only way to tell a retry from a second export.
- **The plan's token allowance reads a rollup, not the views**: the insert adds the delta token points it returned to `org_token_usage` in its transaction, so a retry adds nothing. `server/src/db/plan-allowances.ts`, `server/test-db/plan-allowances.test.ts`.
- **The ingest route returns 5xx only for a genuine write failure** (exporters retry 5xx forever): an unparseable body gets 200, a malformed branch report 400.
- **A branch report's organization comes from the attempt's job id + lease token headers, never from the report's `repo` field** (CWE-862). A refused report writes nothing.
- **An export's organization comes from its attempt's job id + ingest token headers** (or a `fat_` token; github mode refuses neither present, a failed lookup is a 503). They ride the CLI's `OTEL_EXPORTER_OTLP_HEADERS` (env file / Secret ref; a review's own env), never a world-readable file; opencode's entrypoint copies its otel.json with them into a 0600 file under the CLI's HOME, and the tool broker withholds them from every command. The collector forwards them per request (`include_metadata`, `headers_setter`) with no batch processor, which would partition by them for its life. No claim rotates `job.ingest_token`, so an adopted runner keeps exporting. `server/test/auth.enforcement.test.ts`, `server/test-db/job-store.test.ts`, `driver/test/telemetry-shipping.test.ts`, `driver/test/tool-broker.test.ts`, both image `test.sh`.
- **Both executors read `RUNNER_OTEL_ENDPOINT` from a managed-scope file the driver renders root-owned** (`driver/src/telemetry-config.ts`): Claude's managed settings `env` block outranks the container environment and any user- or repo-scope settings; opencode's file is named by `OPENCODE_OTEL_CONFIG_PATH`.
- **The collector exporter sets `compression: none`** — Fastify's JSON parser does not decompress, so gzip means a 400 on every export.
- **No org, repo, job, lease, pod or user id in any metric label value**: labels come from closed vocabularies (route pattern, status class, verb, resource kind, docker command, outcome). A failed scrape-time read omits its samples, never reports zero (`server/test/routes.prometheus.test.ts`).
